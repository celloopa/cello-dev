## Context

Job applications are repetitive, high-stakes, and personal: the same tailoring loop dozens of times, where one invented claim can cost you the interview. That makes it a good place to work out how much a model should do, and where the person has to stay in control.

I've designed Ghosted three times. Each version settled a question the previous one raised.

## Version One: Prove The Workflow

The first Ghosted was a Go terminal app. I wanted to feel the product's constraints directly, so I built it rather than only sketching it. Applications moved through an eight-stage pipeline in plain local JSON. A keyboard-first TUI handled daily review, and a JSON CLI let scripts and AI agents work against the same data. Agents could parse postings and draft documents, but nothing touched the tracker without a dry run or approval.

## Version Two: Minimum Viable Intelligence

In mid-2026 I rewrote Ghosted as a Next.js web app. Early sketches reached for an agent SDK, a headless CMS, and a hosted database. All three were cut because the product hadn't earned them yet. What replaced them fits in one sentence: deterministic code does everything it can, the model only writes prose, and code checks the model.

Code parsed the posting, scored fit from keyword coverage ("/100 fit — computed, not vibes"), and planned the resume changes. Then one bounded call returned the cover letter, rewrites, and answers as JSON. Code checked that output: a 180-word cap on the letter, a banned-phrase list, and honesty flags on any number or tool that didn't appear in the CV. Flagged suggestions weren't deleted. They were marked "source not in CV" for the person to rule on. Export compiled the PDFs with Typst and re-read them the way an applicant-tracking system would, checking that nothing was lost.

The core and the app carried 744 tests between them. Shipping it to testers on a shared subscription taught me the most. The Claude CLI refused the app's own prompt as a suspected injection, so generation moved to Codex. I also closed a hole that would have let any visitor route generations through my account. I wrote up the version-two reasoning in [Minimum Viable Intelligence](/blog/minimum-viable-intelligence).

## Version Three: The Resume Is The Product

Version two had a gap I kept running into. Generated material landed in a separate workspace, while the thing that actually mattered, the resume, sat somewhere else. In October 2026 I rebuilt Ghosted around a single surface: a live resume canvas you can talk to.

- **A live canvas.** The resume renders in the browser with Typst as you work, and the downloaded PDF is compiled by the same engine, so the preview and the file always match.
- **An agent, with a visible approval surface.** A Codex agent tailors the resume to a posting and drafts answers to application questions. Every change it makes is highlighted on the canvas and saved as a version (who, when, and why) that you accept or reject. Undo and restore move a pointer; nothing is deleted.
- **Evidence, not invention.** The base resume is a master copy that's never trimmed. When the agent needs a stronger bullet, it asks for specifics and writes only from what you told it. Job versions are cut to one page from the master.
- **Intake from the source.** A pasted job link goes to the hiring platform's public API first (Greenhouse, Lever, Ashby, Workday, Amazon, Microsoft, and others), falls back to page scraping only when there's no API, and is trimmed to the role, requirements, pay, and benefits.
- **Built to be used by others.** Personal-code accounts with server sync, an admin console for issuing and revoking access, early job categories and "archetype" resumes, and an in-app problem report that sends screenshots straight to me.

### How version three was built

I'm direct about this part because it's part of the design. The flow, the chat-plus-canvas model, the choice to render with Typst, and the product decisions are mine. They're written down as decisions in the repo before any code. A coding agent built the first working version from that spec in a day. That's useful evidence of how I work with AI tools, and it isn't a claim that I hand-wrote every line. The foundations I'm now taking over by hand are the resume data model, the template, the prompts, and version history.

## Outcome And Learning

Ghosted is live at [ghosted.cello.design](https://ghosted.cello.design) and in early testing. Version three is new, so it hasn't earned usage claims yet. Measuring how testers actually use it is the next piece of work.

The lesson across all three versions is the same. Adding AI to a product is easy. The design work is deciding how much the model gets to do, and making sure the person can see, judge, and undo every bit of it.
